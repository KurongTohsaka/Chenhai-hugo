## 1. 数学公式渲染（F1）

### 目标

Markdown 中的 `$...$` 和 `$$...$$` 在浏览器端通过 KaTeX 实际渲染，而非仅保留原始分隔符。

### 实现策略

**自动注入机制**：构建时扫描每页的渲染后 HTML，检测是否包含 KaTeX 数学分隔符。若包含，则在 `<head>` 中注入 KaTeX 资源引用。

### KaTeX 加载

默认内置 KaTeX 文件到主题 `assets/`，构建时复制到 `public/assets/`。config.yaml 可覆盖为 CDN：

```yaml
markup:
  math:
    engine: "katex"          # katex（默认）
    katexCSS: ""             # 空 = 使用内置，可填写 CDN URL
    katexJS: ""              # 空 = 使用内置，可填写 CDN URL
```

### 注入逻辑

渲染管道在输出页面时：
1. 检测内容中是否包含 `class="katex"` 或 `$$` / `$` 模式
2. 若包含则在 `</head>` 前注入 `<link>` + `<script>` 引用
3. 注入 KaTeX auto-render 初始化脚本：
```html
<script>
document.addEventListener("DOMContentLoaded", function() {
  renderMathInElement(document.body, {
    delimiters: [
      {left: "$$", right: "$$", display: true},
      {left: "$", right: "$", display: false}
    ]
  });
});
</script>
```

### 文件变更

- `themes/zhenhai/assets/katex/` — 内置 KaTeX CSS + JS
- `internal/content/renderer.go` — 添加 `ScanForMath` 方法
- `internal/build/builder.go` — 注入 KaTeX 资源
- `themes/zhenhai/layouts/base.html` — KaTeX 注入占位 `{{.Extra.katexAssets}}`

## 2. Mermaid 图表渲染（F2）

### 目标

` ```mermaid ` 代码块在浏览器端实际渲染为图表。

### 实现策略

与 KaTeX 相同模式：检测页面中的 `<pre class="mermaid">` 标签，若存在则注入 Mermaid.js。

### Mermaid 加载

```yaml
markup:
  mermaid: true
  mermaidJS: ""         # 空 = 使用内置，可填写 CDN URL
```

### 注入逻辑

1. 检测内容中是否包含 `class="mermaid"`（Goldmark 自定义渲染器将 mermaid 代码块输出为 `<pre class="mermaid">`）
2. 若包含则注入 Mermaid.js + 初始化脚本：
```html
<script src="/assets/js/mermaid.min.js"></script>
<script>mermaid.initialize({startOnLoad: true, theme: document.documentElement.classList.contains("dark") ? "dark" : "default"});</script>
```

### 文件变更

- `themes/zhenhai/assets/js/mermaid.min.js` — 内置 Mermaid.js
- `internal/content/renderer.go` — mermaid 代码块渲染为 `<pre class="mermaid">`
- `internal/build/builder.go` — 注入 Mermaid 资源

## 3. 图片增强（F3）

### 目标

将 Markdown 标准图片语法 `![alt](url "title")` 渲染为语义化的 `<figure>` 包裹，支持对齐和响应式。

### 渲染规则

```markdown
![镇海](zhenhai.webp "我的秘书舰")
```

渲染为：

```html
<figure class="image-figure">
  <img src="zhenhai.webp" alt="镇海" title="我的秘书舰" loading="lazy">
  <figcaption>我的秘书舰</figcaption>
</figure>
```

### 对齐支持

在 alt 文本末尾添加对齐标记：
- `![镇海 |center](...)` → `<figure class="image-figure image-center">`
- `![镇海 |right](...)` → `<figure class="image-figure image-right">`

### 实现方式

自定义 Goldmark AST 后处理器，在渲染完成后遍历 `<img>` 节点进行包裹。使用 Goldmark 的 `parser.ASTTransformer` 接口。

### 文件变更

- `internal/content/image.go` — 图片增强 AST 转换器
- `themes/zhenhai/assets/css/style.css` — `.image-figure` 样式

## 5. GitHub 图床（F5）

### 目标

支持将本地图片自动上传到 GitHub 仓库作为图床，构建时将 Markdown 中的本地图片路径替换为 GitHub raw URL。

### 双模式

**模式 A：自动上传**

构建时扫描 Markdown 中的相对路径图片引用，将新图片 push 到指定 GitHub 仓库后替换 URL。

**模式 B：URL 映射**

仅做路径替换，不上传。适合图片已手动上传好的场景。

### 配置

```yaml
imageHost:
  enabled: false
  provider: "github"        # github（目前唯一）
  repo: "owner/repo"        # 图床仓库
  branch: "main"            # 分支
  basePath: "images/"       # 仓库内图片目录
  token: ""                 # GitHub Personal Access Token（或通过环境变量 $CHENHAI_IMG_TOKEN）
  mode: "auto"              # auto | map
  baseURL: ""               # 模式 B 自定义映射 URL 前缀
```

### 自动上传流程（模式 A）

1. 扫描所有 Markdown 中的 `![alt](path)` 图片引用
2. 判断 path 是否为本地相对路径（不以 `http` 开头）
3. 读取本地图片文件，通过 GitHub API 上传到仓库
4. 替换 Markdown 中的 `path` 为 `https://raw.githubusercontent.com/{repo}/{branch}/{basePath}{filename}`
5. 图片缓存：已上传过的图片（同文件名同内容 hash）跳过上传

### URL 映射流程（模式 B）

1. 扫描所有 Markdown 中的 `![alt](path)` 图片引用
2. 将本地路径替换为 `{baseURL}/{filename}`
3. 不上传任何文件

### 文件变更

- `internal/imagehost/` — 新包：图床抽象接口 + GitHub 实现
- `internal/build/builder.go` — 构建时调用图床处理
- `internal/config/types.go` — 新增 `ImageHost` 配置结构

## 7. 技术选型

| 组件 | 选型 |
|------|------|
| KaTeX | 内置 v0.16.x（~200KB CSS + JS） |
| Mermaid | 内置 v11.x（~2MB，gzip 后 ~500KB） |
| GitHub API | `go-github` 或原生 `net/http` + REST API |
| 图片处理 | 标准库 `image/*` + 可选 `imaging` 库 |

## 8. 明确不支持

- RSS/Atom Feed
- 多语言（i18n）
- 评论系统
- 图片压缩/格式转换（非图床上传场景）

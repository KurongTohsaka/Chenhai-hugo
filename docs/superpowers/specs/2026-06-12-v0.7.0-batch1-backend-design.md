## P1 — 并发页面渲染

### 现状

`renderPages`（`internal/build/render.go`）串行循环渲染每篇文章，每篇需要 Clone → Parse → Execute Template，100 篇文章约 2s。

### 设计

使用 goroutine + semaphore 控制并发数，不引入第三方库。

```
新增文件: 无（改动 render.go）

renderPages:
  1. 收集所有待渲染的非 draft、非 skipped 页面到 slice
  2. sem := make(chan struct{}, runtime.NumCPU())  // 并发上限 = CPU 核数
  3. 每个页面启动 goroutine:
     - sem <- struct{}{}  // acquire
     - 调用 renderToFile
     - <-sem              // release
     - wg.Done()
  4. sync.WaitGroup 等待全部完成
  5. sync.Mutex 保护进度计数器（rendered/skipped）和错误收集
```

### 关键决策

- **并发数**：`runtime.NumCPU()`，避免过度竞争。模板渲染是 CPU-bound。
- **错误处理**：第一个错误通过 `errCh`（buffered channel，cap=1）收集，其余 goroutine 继续完成当前任务后自然退出（不强制 cancel，避免残留半成品文件）。
- **首页分页**：`renderPaginatedListPages` 保持串行调用（在主 goroutine），因为它内部逻辑简单、耗时极短，且依赖完整 published pages 顺序。
- **线程安全**：`renderToFile` 各写不同文件，无 I/O 竞争。Engine 的 `RenderPage` 内部做 Clone（每次独立 template 实例），天然线程安全。

## P2 — 模板预编译缓存

### 现状

`theme.New()` 每次构建都遍历嵌入/外部/站点三层模板文件并全部 Parse。对增量构建这是重复工作。

`RenderPage()` 每次都：
1. `e.templates.Clone()` — 复制整个模板树
2. `e.readLayoutSource(name)` — 读模板源文件
3. `clone.Parse(string(src))` — 重新解析

### 设计

在 Builder 中缓存 Engine 实例 + 模板源文件内容，跨构建复用。

```
Builder 新增字段:
  cachedEngine  *theme.Engine         // 跨构建复用（模板未变时）
  templateSrcs  map[string][]byte     // 模板源文件缓存（按 name 索引）

build 流程:
  if !templatesChanged && b.cachedEngine != nil:
    复用 b.cachedEngine  // 跳过整个 Engine 创建
  else:
    engine, _ := theme.New(...)
    b.cachedEngine = engine
    // 预热 templateSrcs 缓存
```

### Engine 内优化

`RenderPage` 中 `readLayoutSource` 改为优先从内存缓存读取：

```go
func (e *Engine) readLayoutSource(name string) ([]byte, error) {
    if e.templateSrcs != nil {
        if src, ok := e.templateSrcs[name]; ok {
            return src, nil
        }
    }
    // 原有磁盘/embed 读取逻辑...
    // 读取后存入 e.templateSrcs[name]
}
```

### 关键决策

- Clone + Parse 是 Go template 的固有开销（Execute 后不可 Parse），无法消除，但源文件读取被缓存。
- 跨构建 Engine 复用：Builder 生命周期内（一次 `chenhai serve` 的多次自动构建或一次 `chenhai build`），第一次构建创建 Engine，后续增量构建复用。
- 模板变更检测复用现有 `hasTemplatesChanged()`。

| 文件 | 改动 |
|------|------|
| `internal/content/page.go` | Page 结构体新增 `Pinned bool` |
| `internal/content/frontmatter.go` | fmRaw 新增 `Pinned bool`；validKeys 新增 `"pinned"`；parseFM 赋值 |
| `internal/index/site.go` | BuildSite 排序逻辑改为 pinned 优先 |

### 设计

Front Matter 新增可选字段 `pinned`：

```yaml
---
title: "重要通知"
date: 2026-06-12
pinned: true
---
```

排序逻辑（`BuildSite`）：

```go
sort.Slice(pages, func(i, j int) bool {
    if pages[i].Pinned != pages[j].Pinned {
        return pages[i].Pinned  // pinned=true 排最前
    }
    return pages[i].Date.After(pages[j].Date)  // 同级别按日期倒序
})
```

置顶文章在首页、分类页、标签页均排在最前。模板中 `{{.Page.Pinned}}` 可判断是否渲染置顶标识（后续前端批次处理）。

## T1 — chenhai doctor

### 设计

新增 CLI 命令 `chenhai doctor`，检测站点健康状态。

**新文件**：`internal/cli/doctor.go`

**检测项**（按顺序执行）：

| 检测 | 级别 | 说明 |
|------|------|------|
| config.yaml 存在 | error | 文件缺失则无法继续 |
| config.yaml YAML 语法 | error | 解析失败则报告行号和修复建议 |
| content/ 目录存在 | warning | 目录为空仅 warning |
| Front Matter 校验 | error | 遍历所有 .md，解析失败则报告文件名+错误 |
| 必需模板检查 | error | base.html / single.html / list.html / index.html / 404.html |
| static/ 目录 | warning | 不存在仅提醒 |
| 缓存一致性 | warning | .chenhai-cache.json 中记录的文件缺失则报告 |

**输出风格**：中文友好，格式参考 rustc：

```
🔍 Chenhai Doctor — 站点健康检查

✓ config.yaml 语法正确
✓ content/ 目录存在（12 个分类目录）
✗ content/posts/test.md
  → Front Matter 解析失败：YAML 第 3 行缩进错误
  → 提示：检查是否混用了空格和 Tab
✓ 所有必需模板存在
⚠ static/ 目录不存在（静态资源将跳过）
⚠ 缓存文件 /tmp/test.md 已不存在，将从缓存中移除

✗ 发现 1 个错误，2 个警告
```

**退出码**：有 error → 1，仅 warning → 0。

**CLI 注册**：在 `internal/cli/root.go` 中注册 `doctorCmd`。

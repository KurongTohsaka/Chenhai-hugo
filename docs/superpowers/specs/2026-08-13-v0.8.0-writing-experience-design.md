## 一、T1 — `chenhai image` 贴图工作流

### 现状痛点

内容站 144 篇文章全部手写 `/img/分类/文章/imgN.png` 绝对路径；截图需手动挪入 `static/img/`、手动命名、手动改 md 引用。无 alt 无标题。图床 auto/map 双模式已实现但内容站未启用（config 无 imageHost 段）。

### 命令设计

```
chenhai image add <file> [--post content/posts/xx.md] [--dir <目录>] [--quality 80] [--name imgN] [--force]
chenhai image compress <dir|file> [--quality 80]      # 批量：目录内 jpg/png → webp
chenhai image resize <file> [--width N] [--height N]  # 等比缩放（限制在最大尺寸内，宽高比不变）
```

`add` 行为（核心）：

1. 源图解析：jpg/png → WebP 编码；gif 原样拷贝（不动画帧）；其余格式报错退出
2. 目标目录解析（二选一）：
   - `--post`：取文章相对 `content/` 的路径去 `.md` 后缀，**剥离首个 section 段**（循 Permalink 逻辑，含 `index.md` 去 `/index` 后缀）→ `static/img/<剩余路径>/`（例：`content/posts/CS224N/lesson_5.md` → `static/img/CS224N/lesson_5/`；`about/index.md` → `static/img/about/`）
   - `--dir`：直接指定 `static/` 下相对目录
   - 两者同给报错
   - 注：`image add` 须在站点根目录运行（检测 config.yaml），防误在任意目录建 static/
3. 自动命名：目录内已有 `imgN.webp` 取最大 N+1；`--name` 覆盖；`--force` 允许覆盖同名
4. 输出单行引用：`![](/img/<相对static路径>/imgN.webp)`，供夫君粘贴进 md（Q9 已定：命令式，不做自动插入）
5. 幂等安全：不覆盖未知文件；目标目录不存在自动创建

### 技术选型

- `github.com/chai2010/webp`（cgo 封装 libwebp，C 源码 vendored，`go get` 即用；macOS clang / CI ubuntu gcc 均可编译）。Q14 已定，不做 wasm 方案
  - 供应链知悉：该库最后实质更新约 2021 年，vendored 旧版 libwebp（含历史 CVE 面）；go.sum 锁定版本，本地 CLI 攻击面低（输入为自有文件）可接受；README 注明构建需 C 工具链
- 缩放用 `golang.org/x/image/draw`（纯 Go，无新 cgo 依赖）
- 新包 `internal/imageproc/`：封装 decode / encode webp / resize / 批量扫描；`internal/cli/image.go` 仅做参数与 IO

### 文件清单

| 文件 | 操作 | 职责 |
|------|------|------|
| `internal/imageproc/imageproc.go` | 新建 | Decode/Encode/Resize/Batch 核心逻辑 |
| `internal/imageproc/imageproc_test.go` | 新建 | 编码/缩放/命名测试 |

## 二、T2 — shortcode 组件系统

### 语法（Q12 已定：Hugo 式，块级）

```
{{< tabs "Go" "Java" >}}
=== Go ===
```go
fmt.Println("hi")
```
=== Java ===
```java
System.out.println("hi");
```
{{< /tabs >}}

{{< gallery >}}
![图一](/img/a.png)
![图二](/img/b.png)
{{< /gallery >}}

{{< details "答案" >}}折叠内容，支持**markdown**{{< /details >}}
```

- 定位：**块级** shortcode（v0.8 不支持行内、不支持嵌套——Q10 已定中间态）
- tabs 内部用 `=== 标签名 ===` 分块，规避嵌套解析需求

### 解析设计（Goldmark 扩展，循 Admonition 模式）

1. **ShortcodeBlockParser**（`parser.BlockParser` 实现）：行首 `{{< name ... >}}` 触发进入 raw 收集，逐行累积，遇 `{{< /name >}}`（name 必须匹配）终止；未闭合报错由 transformer 兜底（原样输出 + 日志）
2. 产出 **ShortcodeNode**（`ast.BaseBlock` 子类，含 Name/Params/Content）
3. **ShortcodeRegistry**：`Register(name, RenderFunc)` + `Render(ctx) (string, error)`
   - `RenderFunc` 签名：`func(ctx *ShortcodeContext) (string, error)`
   - `ShortcodeContext{Name string; Params map[string]string; Positional []string; Content string; Page *content.Page}`
   - 参数解析：`key="value"` / `key=value` / 裸词（进 Positional）
4. **内层渲染**：shortcode 内容需要完整 markdown（表格/公式/代码），故 Renderer 持有第二个 goldmark 实例 `innerMD`——与主实例同扩展但**不含** ShortcodeBlockParser（防递归嵌套）；Admonition 继续用 bare 实例不动
5. **主题覆盖接口**（Q10 已定：留接口）：
   - `content` 包定义 `type ShortcodeTemplateProvider interface { LookupShortcodeTemplate(name string) ([]byte, bool) }`
   - `theme.Engine` 实现之：**直接复用 `readLayoutSource("shortcodes/<name>.html")`**（自带站点→外部主题→嵌入主题三层查找 + templateSrcs 缓存 + srcMu 锁，零新代码）
   - 命中 → **独立 `template.New(name).Parse(src)` 实例渲染**（严禁 Parse 进全局模板集——Execute 后 Parse 会 panic，循 RenderPage 的 Clone 规避思路），上下文 `.Params/.Positional/.Content/.ContentHTML/.Page`（ContentHTML 供主题取内层渲染结果）；未命中 → 内置 Go 渲染器
   - 循环依赖规避：content 只依赖接口；注入点在 `build.New()`（builder 已持 renderer+engine，一处覆盖 build/serve 双入口），不涉 cli 层
6. **注册时机**：`internal/content/shortcodes.go` 内 `RegisterBuiltins(reg)` 注册 tabs/gallery/details；NewRenderer 时内置

### 内置组件

| 组件 | 语法 | 输出 |
|------|------|------|
| tabs | `{{< tabs "A" "B" >}}` + `=== A ===` 分块 | `<div class="tabs"><div class="tab-nav"><button>…` + JS 切换；首个默认激活 |
| gallery | 内容 = 多行 `![alt](src)` | `<div class="gallery">` + 每图 `<figure class="gallery-item">` 网格；复用现有图片懒加载（loading="lazy"） |
| details | `{{< details "标题" >}}内容{{< /details >}}` | `<details><summary>标题</summary>…内容(已渲染 markdown)…</details>` |

未注册名称：HTML 注释标记（`<!-- unknown shortcode: xxx -->`）+ 原文透传（作者肉眼可见）；构建期 warning（文件名+行号）留待 v0.9（渲染器暂不持有文件名上下文）。

### 前端

- `themes/zhenhai/assets/css/style.css`：`.tabs/.tab-nav/.tab-panel/.gallery/.gallery-item/details/summary` 样式（水墨风格，明暗双模适配）
- `themes/zhenhai/assets/js/main.js`：tabs 切换逻辑（事件委托，`<div class="tabs">` 容器内 button 点击切换）；gallery/details 无需 JS

## 三、T3 — RSS/Atom 订阅

### 设计

- 构建流程末尾生成 `public/atom.xml`（Atom 1.0，RFC 4287）
- **开关与条件**：config 新增 `rss:` 段 `{enabled bool, limit int}`（默认 enabled=true, limit=20）；`BaseURL` 为空 → 跳过生成 + 构建期 warning；doctor 新增检查项「baseURL 未配置 → RSS 不会生成」（warning 级）
- 字段：feed(title/subtitle/updated=最新文章日期/link self/author=cfg.Author.Name)；entry(title/link=baseURL+Permalink/id/updated=LastMod‖Date/summary=Description，无则正文截断约 300 字)
- **内容策略（v0.8 定稿）**：统一输出摘要——增量构建下未变更文章无全文缓存（collect.go 对增量页面置空 Content），全文/摘要混排会导致 feed 前后不一致；统一摘要保证一致性与实现简单，全文订阅留待缓存体系成熟后
- 取文章：按 Date 倒序前 N 篇，跳过 draft
- 序列化：`encoding/xml` 标准库，结构体 + `xml.MarshalIndent`（零新依赖）
- 主题：`base.html` `<head>` 加 `<link rel="alternate" type="application/atom+xml" title="…" href="/atom.xml">`（baseURL 为空则不输出该 link，避免无效绝对路径）
- 内容站 config.yaml 需补 `baseURL: "https://hekurong.github.io"`（集成验证时落地）

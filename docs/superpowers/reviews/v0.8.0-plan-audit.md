## 🔴 阻断项（必须解决）

### R1. `--post` 目录映射三处互相矛盾，贴图核心路径必然出错
**位置**：设计规格 §一 步骤 2 与示例（design.md:27）↔ 实现计划 Task 3 Step 1 代码（plan:622）↔ 计划内 Long 描述与手动验证预期（plan:589-591、687-688）
**依据**：
- 设计规格：`content/posts/CS224N/lesson_5.md` → `static/img/CS224N/lesson_5/`（**去掉 posts/ 前缀**）
- 实现代码：`relDir = filepath.Join("img", strings.TrimSuffix(post, ".md"))` → `static/img/posts/CS224N/lesson_5/`（**保留 posts/ 前缀**）
- 同一计划内 Long 示例却写 `--post posts/CS224N/lesson_5.md → static/img/CS224N/lesson_5/img3.webp`（无 posts/），手动验证步骤预期 `![](/img/hello/img1.webp)`（无 posts/）——**Long 描述、验证预期、代码三者互斥**
**后果**：按代码实现，输出路径与设计规格、验证预期全部不符；按文档改代码，则验证步骤与示例全错。且内容站 144 篇既有文章全部使用 `/img/分类/文章/imgN.png` 结构（无 posts 前缀），`--post` 生成带 `posts/` 前缀的目录会破坏既有习惯，与 `Permalink()` 的路径结构（`/posts/.../`）也不对应。
**建议改法**：三处统一为一种语义，二选一：
- A（推荐，与既有 `/img/分类/文章/` 习惯一致）：`--post` 取文章相对 `content/` 的路径去 `.md` 后，**剥离首个 section 段**（如 `posts/CS224N/lesson_5.md` → `img/CS224N/lesson_5`；`about/index.md` → `img/about`，注意 index.md 需去 `/index` 后缀，循 Permalink 逻辑）；
- B（语义更简单）：保留完整路径 → `img/posts/CS224N/lesson_5`。
- 无论选哪种，代码、Long 文案、验证步骤三处同步修改；建议补一条自动化测试覆盖目录映射（当前 add 无任何单测，只有手动验证）。

### R2. base.html 的 alternate link 模板代码照抄即整站构建失败
**位置**：实现计划 Task 7 Step 6（plan:1715-1718）

**建议改法**：模板改为 `{{if .Config.BaseURL}}` + `href="{{.Config.BaseURL}}/atom.xml"`；无需给 TemplateData 补字段。

### R3. `chenhai version` 版本号遗漏——v0.7.0 已漏，v0.8 计划仍漏

### R4. Task 4 与 Task 5 任务边界矛盾——Task 4 不可能「测试全绿 + commit」

## 🟡 风险项（建议解决）

### Y1. shortcode 内代码块导致 `data-lang` / `data-hl-lines` 注入错位
**位置**：shortcode 渲染管线（Task 4 Step 3-5）与既有后处理（highlight_lines.go:31-40、131-145）交互处
**依据**：`injectLangLabels` / `injectHLLines` 按「HTML 中 `<pre class="chroma">` 出现顺序」消费「源中 fenced code 顺序」——该假设在 shortcode 出现后被破坏：tabs 内的代码块同样输出 chroma `<pre>`，会抢走为正文代码块准备的标记（tabs 正是为放代码设计的核心场景）。`extractHLLines` 虽在 Convert 前从全源删除 `{hl_lines=[...]}` 标记，但注入端的顺序错位仍会导致 hl_lines 标到错误的代码块上、正文代码块丢失高亮行标注。同理 `extractLangs` 会把 tabs 内的 ```lang 计入，正文 lang 标签错位。
**建议改法**：renderShortcode 输出时用占位 token（如 `\x00SC<n>\x00`）占位，`md.Convert` 完成后统一替换为真实 HTML——占位串不含 `<pre>`，注入后处理天然跳过 shortcode 内部代码块；或对 shortcode 输出先单独跑一遍 `splitLineNumbers`/`injectLangLabels` 再嵌入。计划需补此步，并加一个「tabs 内代码 + 正文 hl_lines 代码共存」的回归测试。

### Y2. RSS 增量构建下旧文章 entry 无全文
**位置**：Task 7 Step 4 的 `generateRSS` 与 collect.go:63 交互
**依据**：增量构建时未变更文章只解析 front matter，`page.Content = ""`（collect.go:63 显式注释）。`generateRSS` 用 `p.Content` 作 `content type="html"`，为空时 omitempty 不输出 → 增量构建后的 atom.xml 里旧文章只有 summary、新文章有全文，feed 内容不一致（内容站日常增量构建是常态）。
**建议改法**：在计划中明确此行为（旧条目降级为摘要模式）并写进 tutorial；或在 rss_test 中加断言（Content=="" 时不输出 content 元素）固化该语义。若要求全文一致，需把 RSS 所需 HTML 纳入缓存体系，成本较高，不建议 v0.8 做。

### Y3. RSS 序列化对非法 XML 字符无防护——单篇文章即可让整站构建失败
**位置**：Task 7 Step 4 `xml.MarshalIndent`（plan:1678）
**依据**：文章 Content/Title/Description 若含 XML 1.0 非法控制字符（\x00-\x08、\x0B、\x0C、\x0E-\x1F，从 Word/网页复制文本常见），`xml.Marshal` 返回错误 → Build() 返回 error → **整站构建失败**，且无降级路径。
**建议改法**：marshal 前对 Title/Description/Content 做非法字符清洗（`strings.Map` 剔除合法集之外字符，保留 \t\n\r），或 marshal 失败时去掉 content 重试；二者选一并在测试中覆盖（构造含 \x01 的 Content）。

### Y4. 主题覆盖接口注入点文件路径错误
**位置**：Task 6 Step 2（plan:1363）——「修改 internal/build/collect.go」
**依据**：`NewRenderer` 不在 collect.go 中调用。实际调用点两处：`internal/cli/build.go:30` 与 `internal/server/server.go:137`（rebuild 内），且 serve 每次 rebuild 都新建 renderer/engine/builder。
**建议改法**：在 `build.New()` 内注入（builder 已持有 renderer+engine 两字段，加一行 `r.Registry().SetTemplateProvider(e)` 即覆盖 build/serve 两条入口），clia 层零改动。

### Y5. LookupShortcodeTemplate 伪代码字段名与 Engine 实际结构不符，模板渲染细节未定义
**位置**：Task 6 Step 1（plan:1335-1357）
**依据**：伪代码用 `e.siteLayoutsDir` / `e.themeDir` / `e.embedded.ReadFile`——实际字段为 `siteRoot` / `extThemeLayoutsDir`（engine.go:40-44），嵌入主题走包级 `zhenhai.FS`，无 `embedded` 字段。照抄编译不过（计划自注「以实际为准」，但执行者需自行修正）。另外更关键：计划只说「命中 → html/template 渲染」却未定义实现——Engine 全局模板集在 Execute 后不能 Parse（现有 RenderPage 用 Clone 规避，engine.go:162），shortcode 模板若 Parse 进全局模板集必然 panic；必须用独立 `template.New(name).Parse(src)` 实例渲染。上下文 `.Content` 是原始 markdown，html/template 会自动转义，主题作者需要 safeHTML——这些边界 tutorial 需写明。
**建议改法**：方法体直接复用 `e.readLayoutSource("shortcodes/<name>.html")`（自带三层查找 + templateSrcs 缓存 + srcMu 锁，零新代码）；模板渲染用独立 template 实例；计划补「独立实例渲染」实现说明；ShortcodeContext 模板上下文建议同时暴露 `.ContentHTML`。

### Y6. 组件 CSS 变量与主题实际体系不匹配，暗色模式失效
**位置**：Task 6 Step 3（plan:1378-1397）
**依据**：计划 CSS 使用 `--border-color` / `--bg-secondary` / `--accent` / `--text`（并自注 fallback），但 style.css 实际变量体系为 `--color-border` / `--color-bg-card` / `--color-text-secondary` / `--color-link` 等（grep 全量 `--color-*`）。fallback 是固定 rgba 值——明色可用，**暗色模式下组件样式不随主题切换**。
**建议改法**：改用实际变量（`--color-border`、`--color-text-secondary`、`--color-bg-card`、`--color-code-bg`、`--color-link` 等），保留 fallback 仅作兜底。

### Y7. style.css 缓存版本号未 bump（?v=17）
**位置**：Task 6 文件清单（plan:1321-1325）与 base.html:22
**依据**：base.html 引用 `/assets/css/style.css?v=17`。只改 CSS 不 bump，线上浏览器（含内容站）继续用缓存旧样式，tabs/gallery/details 样式不生效——样式「改了但用户看不见」。
**建议改法**：Task 6 commit 前将 base.html 的 `v=17` 改为 `v=18`，并列入文件清单。

### Y8. 「构建期 warning（文件名+行号）」设计与实现脱节
**位置**：设计规格 §二 5（design.md:103）↔ Task 4 实现（shortcode.go:859、918-925）
**依据**：设计承诺「未注册名称：原样输出 + 构建期 warning（列出文件名与行号）」，但实现只有 HTML 注释输出，无任何构建期 warning 步骤：渲染器无文件路径上下文（ShortcodeContext.Page 注释为「v0.9+ reserved, nil in v0.8」）；`OpenLine` 用 `text.Segment{}.Line()` 计算——零值 Segment 的 Start=0，`Line()` 恒返回 0，**OpenLine 恒等于 1**（Continue 里也未修正）。验收特性在 v0.8 实现里实际不可达。
**建议改法**：二选一——(a) 删除设计承诺，明确 v0.8 的未知 shortcode 兜底为「HTML 注释 + 原文透传」；(b) 若保留 warning：Renderer 需持有当前文件名（RenderHTML 调用面加参数或 setter），OpenLine 在 Continue 中按已消费行数累加。

### Y9. 分支流程自相矛盾（Task 8 才建 dev-v0.8.0）

**建议改法**：计划开头（Task 1 之前）加一步 `git checkout -b dev-v0.8.0`，所有 Task commit 落在 dev 上。

### Y12. image 命令族无站点根检测

### Y15. chai2010/webp 维护状态与供应链风险（知悉项）
**位置**：T1 技术选型（design.md:36）

**建议改法**：go.sum 锁定版本（go get 后提交 go.sum）；本地 CLI 攻击面低（输入为自有文件）可接受；README 注明构建需 C 工具链；CI 验证 cgo 构建（见 Y16）。

### Y16. CI go 版本与 go.mod 不匹配，v0.8 的「CI cgo 全绿」验收有不确定性
